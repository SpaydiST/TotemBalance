# TotemBalance

Балансирующий плагин, который делает тотемы бессмертия редкостью и ограничивает их использование — отлично подходит для серверов с экономикой, PvP и хардкорными механиками.

## Возможности

- **Редкий дроп тотемов** — шанс выпадения ванильного тотема настраивается отдельно для эвокеров, появившихся в волне рейда, и остальных эвокеров. Тотемы, добавленные другими плагинами к дропу во время события смерти, сохраняются.
- **Перезарядка тотемов** — после срабатывания тотема игрок не может использовать другой тотем в течение заданного времени. Длительность можно переопределить для отдельных миров.
- **Визуальная шкала перезарядки** — на иконке тотема в хотбаре отображается ванильная дуга перезарядки (как у зарядов ветра). Без лишних сообщений в чате.
- **Во время перезарядки** — тотем не срабатывает и не тратится: игрок умирает, а тотем остаётся в руке до окончания перезарядки.
- **Сброс на смерти** — таймер перезарядки сбрасывается при смерти игрока; оставшийся срок хранится в данных игрока, поэтому перезагрузка плагина не обходит активный таймер. При включении плагин также восстанавливает индикаторы уже подключённым игрокам.
- **Перезагрузка настроек** — новые длительности применяются к следующим срабатываниям, активные таймеры сохраняют свой срок. При переходе `cooldown-seconds` с положительного значения на `0` активные таймеры сбрасываются, в том числе у офлайн-игроков. Мировые переопределения при этом продолжают действовать.
- **Совместная работа** — перезарядка начинается только после того, как событие использования тотема завершилось без отмены другим плагином.
- **Полная настройка** — все параметры выносятся в `config.yml`.

## Конфигурация

Файл `plugins/TotemBalance/config.yml`:

```yaml
# Шанс выпадения тотема (от 0.0 до 1.0). 0.05 = 1 из 20
drop-chance: 0.05

# Отдельный шанс для эвокеров, появившихся в волне рейда.
# Если параметр отсутствует, используется drop-chance.
raid-drop-chance: 0.05

# Перезарядка по умолчанию в секундах. 0 сбрасывает активные таймеры;
# переопределения world-cooldowns продолжают действовать.
cooldown-seconds: 60

# Переопределения по точному имени мира; остальные используют cooldown-seconds.
world-cooldowns:
  pvp_arena: 120
  world: 30
```

Длительность для мира выбирается в момент срабатывания тотема. Перемещение между мирами не меняет уже запущенный таймер. Значение `0` в `world-cooldowns` отключает новые таймеры в указанном мире. Если параметр `raid-drop-chance` отсутствует в старом конфиге, используется `drop-chance`.

## Команды

| Команда | Описание |
|---|---|
| `/totembalance reload` | Перезагружает конфиг без перезапуска сервера (право `totembalance.admin`, по умолчанию OP) |
| `/totembalance` | Показывает подсказку по использованию |

## Совместимость

- Целевая версия: **Paper 26.3 build 5-alpha или новее**
- Java: **25**
- Плагин собран против Paper API 26.3. Совместимость со Spigot, CraftBukkit и более старыми версиями Minecraft этой сборкой не заявлена.

## Установка

1. Установи Paper 26.3 build 5-alpha или новее на Java 25.
2. Скачай jar и положи его в папку `plugins`.
3. Перезапусти сервер.
4. При первом запуске создадутся `config.yml` и служебный `cooldown-state.yml` — настрой `config.yml` под себя.
5. После правок конфига используй `/totembalance reload`.

## Как работает механика перезарядки

1. Игрок получает смертельный урон с тотемом в руке → тотем срабатывает, тратится, выдаёт ванильные эффекты (Регенерация II, Поглощение II, Огнестойкость).
2. Запускается перезарядка на время, заданное для текущего мира, — на тотемах в инвентаре видна шкала-дуга.
3. Если игрок снова умирает во время перезарядки, тотем не активируется и не расходуется — игрок умирает, тотем ждёт конца перезарядки.
4. Смерть сбрасывает перезарядку — после респавна тотем работает сразу.

Активные сроки таймеров сохраняются в данных игроков. При отключении глобальной перезарядки увеличивается служебное поколение таймеров в `cooldown-state.yml`, поэтому старые записи офлайн-игроков будут сброшены при следующем входе, даже если перезарядку включили обратно до их возвращения. При выходе игрока его таймер удаляется из оперативного кеша, а сохранённый срок остаётся в данных игрока.
